Octopus Browser Relay System Architecture

Octopus Browser Relay places two protocol gateways around one long-running broker service. Every agent command enters through MCP with an opaque bindingRef, and the broker validates that reference against the authenticated agent before resolving a private extension target. The live version-two deployment currently has three exclusive bindings and three connected Chrome or AdsPower profile extensions; the broker alone owns routing truth.

    Broker-Owned Facts and Derived Target Status

    Register target
    Persist private identity, friendly alias, public key, and policy.
    Track connectivity
    Record whether an authenticated extension socket is connected.
    Track health
    Measure heartbeat freshness, response latency, timeouts, and errors.
    Track occupancy
    Record whether a valid lease currently belongs to another agent.
    Derive status
    Compute available, busy, offline, or error from those facts.
    Version snapshot
    Increment the version whenever any factual dimension changes.
    Expose safe view
    Return alias, factual status, and capabilities without private IDs.
